# Magical-Athlete

《魔法运动会》是一款支持浏览器联机的骰子竞速桌游。创建房间，把六位房间码发给同伴，或添加电脑玩家开始一场四轮比赛。手机和电脑使用同一个网址。

## Windows 开服

推荐 Python 3.12。在项目目录执行一次安装。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

双击 `start.cmd` 开服，也可以在 PowerShell 中运行 `.\start.cmd`。本机打开 [游戏大厅](http://127.0.0.1:8000)。其他设备连接同一局域网，将网址中的 `127.0.0.1` 换成开服电脑的局域网 IPv4 地址（可用 `ipconfig` 查看）。主机防火墙需允许来自游戏局域网的 TCP 8000 入站连接。关闭服务窗口即可停服。

## Linux 服务器

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn server:app --host 0.0.0.0 --port 8000 --workers 1 --ws websockets-sansio
```

一个进程同时提供网页、房间接口和 WebSocket。保持一个 worker，以便同房间的连接共享通知和电脑玩家任务。部署到已有的 HTTPS 网关时，将网页、`/api/` 和 `/ws/` 转发到同一端口，保留 Host 并允许 WebSocket 升级。

### 断网内网安装

在联网的同系统、同架构、同 Python 版本机器上执行 `python -m pip download -r requirements.txt -d wheels`。将项目和 `wheels` 目录复制到内网主机，创建虚拟环境，在该环境中执行 `python -m pip install --no-index --find-links wheels -r requirements.txt`。运行游戏只使用本地素材，不访问外部图片、字体、AI 或 CDN。

### 存档和重连

SQLite 在首次启动时创建 `data/game.db`。也可以通过 `ATHLETE_DB` 环境变量指定文件位置。每次有效操作都会保存当前轮次、骰子、待决选择、座位和得分。备份时先停服，再复制整个 `data` 目录。

同一浏览器刷新页面或网络恢复后会凭本地座位凭证回到房间。服务重启后打开原网址即可续玩。房间码用于加入未开赛的房间，个人座位凭证由浏览器保存。进行中的房间需要使用原浏览器和原网址恢复。

## 玩法

- 房间最多 8 人，真人和电脑都占一个座位。按实际角色池检查开局条件，每位玩家需要 2 名不同角色。当前的 7 张角色卡支持两人和三人局，8 人局需要 16 张。
- 随机起选后，先顺时针、再逆时针各选一次。三人及以上每两轮重新选角，前后两轮派不同角色。两人局每轮重选，两名角色同时出场，可以指定先后并分配双骰。同一玩家可以包揽金银奖杯。
- 第 2 名角色冲线时立即结束本轮。四轮金奖杯依次为 3、4、4、5 分，银奖杯为 1、2、2、3 分。地图得分在落点结算时计入当轮。最终按总分从高到低、四轮平均名次从低到高排名。
- 两人局取该玩家本轮表现最好的角色名次。未冲线按所在格排序，同格并列。总分和平均名次都相同的玩家共享最终名次。
- 标准地图每 5 格的数字标示距离。狂热地图的星星得 1 分，TRIP 跳过下次主要移动，箭头按标示方向和距离移动。传送和放置保留各自的行动类型，新落点同样结算地图。越过终点算冲线。
- 模仿猫复制仍在赛道上的领跑者；独自领先时暂时失去复制能力，并列时由它选择其他领跑者。巨婴允许经过，停入它所在格的角色改放在后方 1 格；巨婴主动进入有人的格子时将原有角色放到后方 1 格。起点可以共享。

### 本版的结算约定

房主建房时选定整场地图。每轮由本次选角的起选玩家先行动。两人局先指定行动顺序，再处理掷骰前选择、掷两枚 D6、分配点数，然后按指定顺序结算两名角色。使用慢跑或因绊倒跳过主要移动的角色无需骰子。如果只有一名角色需要骰子，就从两枚中选一枚；都不需要时直接结算。起哄者比较每名行动角色在玩家回合开始与该角色行动结束时的格子。

## 测试与扩展

在已安装依赖的环境中运行 `python -m unittest discover -s tests -v`。测试包含七名角色的触发和边界、两张地图、两人及三人的四轮比赛、两个真实 HTTP/WebSocket 客户端的同步、服务重启续玩以及服务端人机对战。网络测试使用临时端口和独立的临时数据库。

| 文件 | 用途 |
| --- | --- |
| `game.py` | 角色表、地图格、可保存的回合步骤、选角、奖杯和电脑策略 |
| `server.py` | 座位凭证、房间操作、SQLite 存档、WebSocket 广播 |
| `static/` | 浏览器界面、两张地图和七张角色卡的 WebP 素材 |
| `tests/` | 规则测试与真实网络对局测试 |

添加角色时，在 `CARDS` 中登记名字和卡面说明，在对应时点实现能力，并将同名 WebP 卡图放进 `static/assets/`。选角池、人数校验和网页图鉴会读取完整角色表。
